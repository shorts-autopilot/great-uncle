# Completeness ledger

Generated by `python3 tools/spec_status.py`; edit the classification tables in that script, not this file. The same tables write `spec/matrix.json`.

## What "complete" means

A row is classified when it has one of the statuses below. An `out-of-scope` row additionally needs a reason. Every chapter has a deliberate default, so a newly crawled chapter cannot appear as an implicit `not-started` row.

This ledger records scope and implementation evidence; it does not claim that a `not-started` or `in-progress` row works. `verified` is reserved for behaviour proven on real DMX hardware, and no row uses it yet.

| in-progress | 81 | Part of the feature exists; the rest is deferred. |
| not-started | 705 | Not built, or not designed yet. |
| out-of-scope | 387 | Not a feature of this product; reason recorded below. |

## Cross-cutting designs not owned by one chapter

These are the gaps that a chapter-by-chapter audit would otherwise hide. Ranked by value to a working desk.

1. **Colour model** — `ColorSub_*`/CMY, HSB, colour wheels, CTO and gels. Additive RGB only is wrong for a large class of real profiles; affects palettes, cues, effects and the GUI swatch.
2. **DMX In and merge** — The `dmx` chapter's first row is only half built: the transport is write-only, so there is no backup desk, house console or DMX-triggered snapshot.
3. **RDM** — Discovery and remote patching; shares the bidirectional transport work with DMX In.
4. **MAtricks, Shuffle and Align** — Programming speed for multi-fixture edits; the whole `matricks` chapter and `Align` are unbuilt.
5. **Recipes and Generator** — Look generation beyond a single waveform; `recipes`, `generator` and recipe presets are unbuilt.
6. **Executor pages and special executors** — The executor list is flat; pages, assignments and special executors are missing.
7. **Timecode depth** — Tracks, markers, MTC and an OSC feed hook landed with item 15; OSC ingestion and track groups remain.
8. **Macros and CLI ergonomics** — Macros, variables, transaction undo and machine-readable status are item 16.
9. **Layouts, Quickeys and windows** — Layouts/Quickeys have no design; the five-pane GUI is item 18.
10. **Agenda and timers** — Scheduled events, stopwatch and countdown are unbuilt.
11. **Plugins/Lua** — 164 rows, the largest undecided chapter. Decide between an embedded Lua host and a native plugin API before claiming completeness.
12. **Show Creator** — Import/export and preset/group creation from fixture types; no design yet.
13. **File management and backup** — Backup/template shows, a file browser and show organisation need a design.
14. **Remote inputs** — MIDI, DMX and DC remotes; item 12 only covers OSC/web and item 15 only covers MTC.
15. **Small metadata features** — Appearances, notes, tags, data pools and XYZ are small designs that still need to exist for a full manual replica.

## How rows were classified

- **Phase tables** — the explicit audit in `tools/spec_status.py` for the chapters Phases 1–4 implemented.
- **Chapter defaults** — the deliberate disposition for every row not named individually. A chapter without a default fails the check.
- **Command keywords** — a keyword the parser recognises is `in-progress`; it means the word exists, not that the manual's full behaviour is audited.
- **Out-of-scope** — every such row carries the chapter reason printed above; `--check` fails if one is missing.
- **Row refinements** — `EXTRA` records the cases where the full-manual audit found a status the phase table did not anticipate.

## Verification

```bash
python3 tools/spec_status.py --check
```

The check fails when `spec/matrix.json`, `spec/matrix.md` or this ledger is stale, when a row has no classification, or when an out-of-scope row has no reason.
